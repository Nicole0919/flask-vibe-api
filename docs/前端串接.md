# 個人記帳系統前端串接規格與專案分析

本文件由前端開發設計師角度出發，依據 [交換格式.md](./交換格式.md) 與 [資料表設計.md](./資料表設計.md) 進行專案分析，作為手機客戶端介面（Mobile Web / Native App）串接後端 Flask REST API 之主要技術規範。

---

## 一、 共通規則

### 1. 外層固定封裝結構（三個鍵）
所有 API 回應的 JSON 外層結構一律包含三個固定鍵，不可增減外層鍵名：
- `code`（`integer`）：HTTP 狀態碼（例如 `200`、`201`、`400`、`404`、`500`），外層 `code` 數值與 HTTP 協定標頭的狀態碼完全一致。
- `message`（`string`）：給人類閱讀的提示訊息（繁體中文）。成功時傳回友善提示，失敗時傳回固定人話；絕不包含底層資料庫表名、約束代碼、SQL 語句或例外呼叫堆疊。
- `data`（`object` / `array` / `null`）：實際業務承載資料。
  - 單筆資源查詢或異動成功：回傳 JSON 物件（`{}`）。
  - 清單型資源查詢成功：回傳 JSON 陣列（`[]`），若無符合條件之資料時回傳空陣列 `[]`。
  - 請求失敗（`4xx`、`5xx`）或單筆資源查無資料時：**一律明確回傳 `null`**。

### 2. 成功與失敗的 HTTP 狀態碼
前端依據 HTTP 狀態碼進行流程分流：
- `200 OK`：成功取得資源（GET）、成功更新部分欄位（PATCH）、成功作廢交易或執行發票開獎對獎（POST 操作）。清單無資料亦為 `200`（`data: []`）。
- `201 Created`：成功建立新資源（POST）。`data` 回傳該筆新紀錄在資料庫持久化後的完整內容（含後端產生之 `id` 與時間戳記）。
- `400 Bad Request`：客戶端傳入資料格式錯誤、必填欄位缺漏、數值非正數、業務邏輯檢核失敗（如賣出股數大於目前庫存、重複請領發票中獎、轉出與轉入為同一帳戶）或違反唯一約束。`data` 固定為 `null`。
- `404 Not Found`：請求的路徑不存在，或指定之單一資源識別碼（ID）於資料庫中不存在。`data` 固定為 `null`，提示訊息為「`找不到這一筆`」。
- `500 Internal Server Error`：伺服器內部非預期例外或資料庫暫時斷線、連線逾時。`data` 固定為 `null`。

### 3. 客戶端不送的欄位
客戶端在發送 `POST`（新增）或 `PATCH`（修改）請求的 JSON 載荷時，**嚴禁傳送亦不需要傳送下列由系統管理的欄位**；若前端不慎傳入，後端一律忽略不採用：
- `id`：資料庫自增整數主鍵（BigInteger Identity）。
- `created_at`：資料建立時間戳記，由後端/資料庫自動賦予當前 UTC 時間。
- `updated_at`：資料更新時間戳記，由後端於更新成功時自動刷新當前 UTC 時間。

### 4. 日期、時間與數值型別定義
- **日期（Date）**：一律採用 ISO 8601 日期字串，格式為 `YYYY-MM-DD`（例如 `"2026-11-14"`）。禁止傳入其他格式（如 `YYYY/MM/DD` 或時間戳）。
- **時間戳記（Timestamp）**：後端回傳一律為 UTC 之 ISO 8601 格式字串（例如 `"2026-11-14T03:19:27.523342+00:00"`），前端應轉換為本地時區呈現。
- **金額與數值（Amount / Price / Quantity / Rate）**：在 JSON 中**一律呈現為數值型別（JSON `number`）**，嚴禁加上千分位逗號、貨幣符號或包裝成字串（例如：`70.0`、`500.0`、`10.0`、`1.0`）。
- **幣別代碼（Currency）**：一律為 3 碼大寫 ISO 4217 英文字母（例如 `"TWD"`、`"USD"`、`"JPY"`），預設為 `"TWD"`。

### 5. 可空欄位之表現行為
- 資料庫定義為可空（Nullable）的欄位，在回應 JSON 中若無值**一律明確呈現為 `null`**，不會從 JSON 鍵中消失。
- 客戶端送出請求時，針對選填或可為空的欄位，傳入 `null` 與直接省略該鍵名具備相同效果。

## 二、 錯誤句子表

所有對外暴露的 API 錯誤回應保證只向客戶端傳達清晰易懂的繁體中文人話。
**重要安全性宣告：資料庫表名（Table Name）、約束名稱（Constraint Name）、SQL 語法（SQL Query / SQLSTATE）與例外堆疊（Stack Trace）絕不出現在 JSON 回應中**，僅記錄於後端伺服器內部日誌以供排查。

| 內部錯誤分類代碼（`error_code`） | HTTP 狀態碼 | 客戶端友善句子（人話 `message`） | 觸發原因與業務情境說明 |
| :--- | :---: | :--- | :--- |
| `conflict.unique_name` | 400 | 帳戶名稱已存在，請使用其他名稱 / 分類名稱已存在，請使用其他名稱 | 帳戶、入帳分類或花費分類之名稱重複違反唯一性約束 |
| `conflict.unique_number` | 400 | 發票號碼已存在，請勿重複建立 | 統一發票號碼已被登錄過 |
| `conflict.unique_period_tier` | 400 | 該期別已有相同獎項與獎號設定，請勿重複新增 | 同一開獎期別下重複建立相同級別與號碼之獎項 |
| `conflict.unique_market_symbol` | 400 | 此市場與代號的投資標的已存在，請勿重複建立 | 相同的市場與證券代號標的已存在 |
| `conflict.unique_invoice_income` | 400 | 此發票已有中獎入帳紀錄，請勿重複請領 | 該張中獎發票已產生過入帳流水，不可重複請領 |
| `conflict.unique_trade_income` | 400 | 此交易已產生入帳紀錄，不可作廢 | 投資交易（股利/減資）已關聯入帳紀錄，系統拒絕作廢 |
| `validation.invalid_amount` | 400 | 金額必須大於 0（或數值格式不正確） | 金額、單價、數量或小計為非正數、非數值或負數 |
| `validation.invalid_fx_rate` | 400 | 匯率必須大於 0（或匯率數值格式不正確） | 換算新台幣匯率非正數（$\le 0$） |
| `validation.invalid_format` | 400 | 格式不正確（或發票號碼/期別/幣別/統編格式不正確） | 發票號碼非 2 英文+8 數字、統編非 8 碼、幣別非 3 碼大寫、期別非合規雙月份 |
| `validation.empty_fields` | 400 | 來源與備註至少需填寫一項 / 商家與備註至少需填寫一項 | 記帳明細缺乏可供識別之文字依據 |
| `validation.insufficient_shares`| 400 | 欲扣減之股數大於目前持有股數 | 執行賣出或減資時，異動股數超過目前動態試算之累積持股 |
| `foreign_key.not_found` | 400 | 指定的帳戶/分類/標的/發票不存在 | 外鍵指向不存在之父層實體 ID |
| `foreign_key.restrict` | 400 | 資料已被其他項目參照，無法異動或刪除 | 欲刪除或作廢之項目已被子項目參照保護 |
| `not_found.record` | 404 | 找不到這一筆 | 查無指定的資源 ID 或路由不存在 |
| `upstream.twse` | 502 / 504 / 400 | 證交所目前沒有回應 | 外部台灣證券交易所報價伺服器連線異常、逾時或休市無回應 |
| `database.connection_error` | 500 | 資料庫暫時連不上 | 後端資料庫連線逾時、斷線或連線池耗盡 |

> **備註**：前端處理全域錯誤時，若後端未傳回特定自訂訊息，400 標準兜底人話為「`資料格式不正確或違反約束條件`」，404 兜底人話為「`找不到這一筆`」，500 兜底人話為「`資料庫暫時連不上`」。

## 三、 端點規格一覽

> **範例說明**：以下範例中的資源識別碼 `id` 皆以數字展示，實際使用請以 API 實際回傳值為準。

### 1. 健康檢查 API

#### 1.1 伺服器健康檢查
- **方法**：`GET`
- **路徑**：`/api/health`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：
  - `status`（`string`）：服務狀態，正常為 `"ok"`
  - `time`（`string`）：當前伺服器 UTC 時間戳記
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "伺服器運作正常，測試正常可以進行其他任務。",
  "data": {
    "status": "ok",
    "time": "2026-11-14T03:19:27.523342+00:00"
  }
}
```

#### 1.2 資料庫連線健康檢查
- **方法**：`GET`
- **路徑**：`/api/health/db`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：
  - `status`（`string`）：資料庫連線狀態，正常為 `"ok"`
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "資料庫連線正常",
  "data": {
    "status": "ok"
  }
}
```

### 2. 帳戶 API（Accounts）

#### 2.1 查詢帳戶清單
- **方法**：`GET`
- **路徑**：`/api/accounts`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：陣列，每個元素包含：
  - `id`（`integer`）：帳戶唯一識別碼
  - `name`（`string`）：帳戶名稱
  - `kind`（`string`）：帳戶類別（`cash`、`bank`、`credit_card`、`broker`）
  - `currency`（`string`）：計價幣別代碼
  - `opening_balance`（`number`）：期初餘額
  - `statement_day`（`integer` / `null`）：信用卡結帳日
  - `payment_day`（`integer` / `null`）：信用卡繳款日
  - `created_at`（`string`）：建立時間
  - `updated_at`（`string`）：更新時間
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "查詢成功",
  "data": [
    {
      "id": 1,
      "name": "現金錢包",
      "kind": "cash",
      "currency": "TWD",
      "opening_balance": 0.0,
      "statement_day": null,
      "payment_day": null,
      "created_at": "2026-11-14T03:19:27.523342+00:00",
      "updated_at": "2026-11-14T03:19:27.523342+00:00"
    }
  ]
}
```

#### 2.2 建立新帳戶
- **方法**：`POST`
- **路徑**：`/api/accounts`
- **查詢參數**：無
- **請求欄位**：
  - `name`（`string`，必填）：帳戶名稱，全系統唯一
  - `kind`（`string`，必填）：帳戶種類（限 `cash`、`bank`、`credit_card`、`broker`）
  - `currency`（`string`，選填）：3 碼大寫幣別，預設 `"TWD"`
  - `opening_balance`（`number`，選填）：期初餘額，預設 `0.0`
  - `statement_day`（`integer`，選填）：信用卡結帳日（1~31）
  - `payment_day`（`integer`，選填）：信用卡繳款日（1~31）
- **成功時 `data` 的欄位**：同單一帳戶物件
- **最小 JSON 範例**：
```json
{
  "code": 201,
  "message": "帳戶建立成功",
  "data": {
    "id": 1,
    "name": "玉山銀行",
    "kind": "bank",
    "currency": "TWD",
    "opening_balance": 10000.0,
    "statement_day": null,
    "payment_day": null,
    "created_at": "2026-11-14T03:19:27.523342+00:00",
    "updated_at": "2026-11-14T03:19:27.523342+00:00"
  }
}
```

#### 2.3 查詢單一帳戶詳情
- **方法**：`GET`
- **路徑**：`/api/accounts/<account_id>`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：同單一帳戶物件
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "查詢成功",
  "data": {
    "id": 1,
    "name": "玉山銀行",
    "kind": "bank",
    "currency": "TWD",
    "opening_balance": 10000.0,
    "statement_day": null,
    "payment_day": null,
    "created_at": "2026-11-14T03:19:27.523342+00:00",
    "updated_at": "2026-11-14T03:19:27.523342+00:00"
  }
}
```

#### 2.4 部分更新帳戶
- **方法**：`PATCH`
- **路徑**：`/api/accounts/<account_id>`
- **查詢參數**：無
- **請求欄位**（至少提供一項）：
  - `name`（`string`，選填）：新帳戶名稱（不可與其他帳戶重複）
  - `statement_day`（`integer` / `null`，選填）：結帳日（1~31）
  - `payment_day`（`integer` / `null`，選填）：繳款日（1~31）
- **成功時 `data` 的欄位**：更新後之完整帳戶物件
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "帳戶更新成功",
  "data": {
    "id": 1,
    "name": "玉山主帳戶",
    "kind": "bank",
    "currency": "TWD",
    "opening_balance": 10000.0,
    "statement_day": null,
    "payment_day": null,
    "created_at": "2026-11-14T03:19:27.523342+00:00",
    "updated_at": "2026-11-14T03:25:00.000000+00:00"
  }
}
```

### 3. 帳戶餘額查詢 API（Balance）

#### 3.1 動態試算帳戶餘額
- **方法**：`GET`
- **路徑**：`/api/accounts/<account_id>/balance`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：
  - `account_id`（`integer`）：帳戶識別碼
  - `currency`（`string`）：帳戶主計價幣別

- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "查詢餘額成功",
  "data": {
    "account_id": 1,
    "currency": "TWD",
    "balance": 200.0,
    "balance_twd": 200.0
  }
}
```

### 4. 帳戶移轉 API（Transfers）

#### 4.1 查詢移轉紀錄清單
- **方法**：`GET`
- **路徑**：`/api/transfers`
- **查詢參數**：無
- **請求欄位**：無
- **成功時 `data` 的欄位**：陣列，每個元素包含：
  - `id`（`integer`）：移轉唯一識別碼
  - `transferred_on`（`string`）：移轉日期（`YYYY-MM-DD`）
  - `amount`（`number`）：移轉金額
  - `currency`（`string`）：幣別代碼
  - `fx_rate_to_twd`（`number`）：換算新台幣匯率
  - `from_account_id`（`integer`）：轉出帳戶 ID
  - `to_account_id`（`integer`）：轉入帳戶 ID
  - `note`（`string` / `null`）：備註說明
  - `created_at`（`string`）：建立時間
  - `updated_at`（`string`）：更新時間
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "查詢成功",
  "data": [
    {
      "id": 1,
      "transferred_on": "2026-11-14",
      "amount": 200.0,
      "currency": "TWD",
      "fx_rate_to_twd": 1.0,
      "from_account_id": 2,
      "to_account_id": 1,
      "note": "提款",
      "created_at": "2026-11-14T03:20:05.112233+00:00",
      "updated_at": "2026-11-14T03:20:05.112233+00:00"
    }
  ]
}
```

#### 4.2 建立移轉紀錄
- **方法**：`POST`
- **路徑**：`/api/transfers`
- **查詢參數**：無
- **請求欄位**：
  - `transferred_on`（`string`，必填）：發生日期（`YYYY-MM-DD`）
  - `amount`（`number`，必填）：移轉金額（必須 $>0$）
  - `currency`（`string`，必填）：幣別代碼（3 碼大寫英文）
  - `fx_rate_to_twd`（`number`，必填）：對台幣匯率（必須 $>0$，台幣為 `1.0`）
  - `from_account_id`（`integer`，必填）：轉出帳戶 ID
  - `to_account_id`（`integer`，必填）：轉入帳戶 ID（不得與轉出帳戶相同）
  - `note`（`string`，選填）：備註說明
- **成功時 `data` 的欄位**：同移轉紀錄物件
- **最小 JSON 範例**：
```json
{
  "code": 201,
  "message": "移轉記錄建立成功",
  "data": {
    "id": 1,
    "transferred_on": "2026-11-14",
    "amount": 200.0,
    "currency": "TWD",
    "fx_rate_to_twd": 1.0,
    "from_account_id": 2,
    "to_account_id": 1,
    "note": "ATM提款200元至現金錢包",
    "created_at": "2026-11-14T03:20:05.112233+00:00",
    "updated_at": "2026-11-14T03:20:05.112233+00:00"
  }
}
```

### 5. 入帳分類 API（Income Categories）

- **路徑**：`/api/income-categories`

- **請求欄位**：無
- **成功時 `data` 的欄位**：陣列，每個元素包含：

{

  "data": [
    {
      "id": 1,
      "name": "薪水",
      "description": "正職收入",

      "updated_at": "2026-11-14T04:00:00.000000+00:00"

  - `income_twd`（`number`）：當月所有入帳折合新台幣總額（無紀錄時為 `0.0`）
  - `expense_twd`（`number`）：當月所有花費折合新台幣總額（無紀錄時為 `0.0`）
- **最小 JSON 範例**：
```json
{
  "code": 200,
  "message": "查詢月度收支摘要成功",
  "data": {
    "month": "2026-08",
    "income_twd": 500.0,
    "expense_twd": 70.0
  }
}
```

## 五、 現行交換格式缺少之端點說明

經完整對比 [交換格式.md](./交換格式.md) 及 Flask 後端實作，以下 3 支股市報價相關端點在目前的交換格式與後端程式碼中**均未定義或尚未實作**，前端不應自行憑空發明呼叫，待後端未來擴充後再行串接：

1. **抓取台股報價端點（缺少）**：
   - 缺漏描述：現行系統尚無對接外部證券交易所（TWSE）並將最新報價抓取存檔之 API（例如 `POST /api/quotes/sync` 或 `POST /api/quotes/fetch-twse`）。
   - 影響：若未來實作，當連線證交所逾時或失敗時，預期將回傳錯誤分類碼 `upstream.twse`，前端應顯示友善提示句子「**證交所目前沒有回應**」。
2. **報價清單端點（缺少）**：
   - 缺漏描述：現行系統尚無批次查詢所有已追蹤股票最新市場報價行情之端點（例如 `GET /api/quotes`）。
3. **單筆最新報價端點（缺少）**：
   - 缺漏描述：現行系統尚無依標的 ID 或股票代號取得即時市場報價之端點（例如 `GET /api/instruments/<id>/quote` 或 `GET /api/quotes/<symbol>`）。
4. **其他開獎期別清單端點（缺少）**：
   - 缺漏描述：現行系統提供了 `POST /api/draw-periods` 建立期別，但未提供 `GET /api/draw-periods` 查詢已建立之期別清單端點。前端在選擇期別時需由前端按雙月規則產生 `YYYY-MM` 字串或由發票開立日換算推導。

## 六、 兩份文件的差異

此節逐條比對 [交換格式.md](./交換格式.md) 與 [資料表設計.md](./資料表設計.md) 的欄位名稱、資料型別、可空性與約束條件之具體差異。前端與後端介接時**一律以 [交換格式.md](./交換格式.md) 實際對外呈現為準**：

| 業務模組 / 資料表 | 項目 / 欄位 | 《交換格式.md》（現行 API 實作） | 《資料表設計.md》（底層架構設計） | 差異分析與前端串接相容指引 |
| :--- | :--- | :--- | :--- | :--- |
| **帳戶（Accounts）** | 帳戶種類欄位名與枚舉 | 欄位名為 `kind`；允許值為 `cash`、`bank`、`credit_card`、`broker`。 | 欄位名為 `account_type`；允許值為 `cash`、`bank`、`credit_card`、`brokerage`。 | 交換格式採 `kind` 且券商帳戶為 `broker`；前端送出與解析請一律使用 `kind: "broker"`。 |
